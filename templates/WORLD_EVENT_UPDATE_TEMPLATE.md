# Xuanling Realm — World Event Update Proposal

Use this template when a gameplay outcome has a persistent effect on the shared world and someone wants to submit it for repository review.

**Important:** This is a proposal only. Submitting it does not save the event or make it canon. The repository owner/admin reviews and commits accepted changes. Do not use this template for ordinary character-only progress.

- **Confirmed Outcome:** State only what gameplay resolution established. Separate success, partial success, failure, interruption, and uncertainty.
- **Evidence / Source:** Conversation date and timestamp, relevant resolved scene, and/or approved save reference. Do not fabricate evidence.
- **Involved Actors:** Separate confirmed participants from suspected or rumored participants.
- **Persistent World Effects:** List each lasting consequence and its basis.
- **Knowledge Distribution:** Public facts / witnessed facts / faction knowledge / rumor / hidden information.

- **Related Canon Files:** Relevant world modules and mechanics modules.
- **Proposed Registry Change:** Exact text to add, edit, resolve, or supersede in `world/DYNAMIC_EVENTS.md`.
- **Other Canon Files Requiring Review:** Only files directly affected by the confirmed outcome.
- **Uncertainties / Conflicts:** Use `???` where appropriate. Do not fill gaps by guessing.

- **Admin Decision / Commit Reference:** Filled only by the repository owner/admin after review.

## Review Checklist

- [ ] The action was resolved in gameplay; it is not merely a declared intention.
- [ ] The claimed outcome is supported by a recorded source.
- [ ] The consequence is significant and persistent enough for the shared world registry.
- [ ] No unsupported facts, NPC knowledge, rewards, casualties, territory changes, or mechanics were invented.
- [ ] The proposal does not contradict existing event records or canon without documenting the conflict.
- [ ] Relevant official modules were consulted.
- [ ] Character-only state changes are kept out of the world-event registry.
- [ ] The owner/admin has reviewed and committed the accepted update.
- [ ] The committed event record and status have been verified.

## After Approval

The owner/admin copies the accepted record into `world/DYNAMIC_EVENTS.md`, updates any directly affected canonical world file only when the change is warranted, and verifies the resulting repository state. Until then, keep the proposal outside the active canon and do not narrate it as an established saved event.
